I’m a computer science student at Cal Poly, San Luis Obispo, and a software engineer at the AWS Cal Poly Digital Transformation Hub.

At DxHub I turn public-sector problems into focused cloud prototypes: a property-tax research assistant for the State of Wisconsin, and a case-scoped evidence assistant for the Sacramento County District Attorney.

I care as much about the decisions beneath the interface as the interface itself. That means the retrieval, the infrastructure, the cost model, the eval set, and the doc that explains why it all works.

(How I work) 06 principles
P—01

Understand before building

I want to know how a system works well enough to draw it on a whiteboard before I trust it.

P—02

No band-aids

Fix the root cause. Never special-case one piece of data just to make a single test pass.

P—03

Decisions on paper

ADRs, design docs and API specs, so the next engineer gets the reasoning along with the code.

P—04

Measure with real data

Cost models from the actual bill. Evals graded against what testers actually complained about.

P—05

Careful with production

Deploy after hours, ask before expensive runs, and treat client systems like someone else’s house.

P—06

Above and beyond, early

Scope ambitiously from day one, then protect the team’s time while doing it.
