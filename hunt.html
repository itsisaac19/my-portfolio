01The problem

Live data only matters if people can act on it.

Mid-event, admins need to know where every team is, which checkpoints they’ve cleared, when photos come in and whether the clock is running, all while the game keeps going.

The dashboard combines several backend streams into one shared view, without competing with the system that runs the participant experience.

02System

A safe boundary on a shared table.

The participant backend and the dashboard share a DynamoDB table, but not ownership of it. The dashboard only reads backend records and writes two additive item types of its own: checkpoint events and dashboard controls. Start, pause and reset live on a dashboard-owned item that gets merged in at read time, so an operations tool can never become a second writer to core game state.

03My part

Map, routes, infra, all of it.

  1. Live map. Team positions, trails, progress views, timers and checkpoint notifications.
  2. Event-driven photos. Checkpoint photos flow from S3 through Lambda into the dashboard feed.
  3. Resilient polling. Exponential backoff and scoped event handling, so the dashboard degrades safely when services go down.
  4. Separated privileges. Viewer access is split from game-control actions, which sit behind a separate secret validated on the server.
  5. Golden-angle team colors. Team colors are spaced by the golden angle, so they stay distinct however many teams join.
